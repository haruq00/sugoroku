# すごろく×ローグライク プロトタイプ

## 1. フォルダ構成

```
sugoroku-roguelike/
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── config.js   … バランス数値・盤面内訳・ノルマ・パッシブ/カード/お守り/武器/ショップ定義
│   ├── rarity.js   … アイテムのレア度（解禁ゲーム数・重み付き抽選・色）の共通処理
│   ├── assets.js   … 画像読み込みの一元管理（無ければCSS/絵文字で仮表示）
│   ├── sound.js    … 効果音（ファイルが無ければ合成音でフォールバック）
│   ├── events.js   … 将来のカード/パッシブ用イベントフック
│   ├── board.js    … すごろく盤（長方形の外周リング）の生成・描画・移動・ランダム化
│   ├── dice.js     … サイコロUI（複数個対応・振るモーション）
│   ├── combat.js   … 複数敵・全体攻撃(AOE)・武器ダメージ・GAMEスケーリング対応の自動戦闘
│   ├── shop.js     … ショップ（武器/お守り購入、リロール、カード/お守り削除）
│   ├── ui.js       … 画面表示・演出（DOM操作専門）
│   ├── menu.js     … 左端MENU（ステータス/カード/パッシブ/お守り確認画面）
│   ├── debug.js    … デバッグパネル（強制出目、攻撃力/クリ率の自由編集）
│   └── main.js     … 起動処理・画面フィット
└── assets/
    ├── player/, monsters/, tiles/, ui/, sfx/, passives/, cards/, omamori/, weapons/ … 素材置き場（現在は空）
```

## 2. 実行方法

`index.html` をブラウザで直接開くだけで遊べます。

- 起動直後：最初に1回だけパッシブを選ぶ画面が出ます。
- 盤面の🛒マス（ショップ）に止まると、武器・お守りの購入やカード/お守りの削除ができます。ショップ画面は縦にスクロールでき、右上の「閉じる」ボタンか、パネル外側の暗い部分をクリックすると退出できます。
- 右上の **DEBUG** ボタン：出目の強制指定、攻撃力／クリティカル率の増減。
- 左上の **MENU** ボタン：ステータス（装備武器含む）、獲得したカード・パッシブ・お守りの一覧確認（レア度に応じて名前の色が変わります）。

| 戦闘・サイコロ・移動のテンポ（速さ）を変える | `js/config.js` の `BATTLE_*_MS` / `DICE_*_MS` / `PRE_MOVE_DELAY_MS` / `BOARD_STEP_DELAY_MS` |
| マスの内訳（数）を変える | `js/config.js` の `CONFIG.STAGES.<ステージ名>.counts` |
| パッシブ／カード／お守り／武器を追加・変更する | `js/config.js` の `CONFIG.PASSIVES` / `CARDS` / `OMAMORI` / `WEAPONS`（`rarityId`を指定） |
| レア度の色・解禁ゲーム数を変える | `js/config.js` の `CONFIG.ITEM_RARITIES`（`color` / `unlockGame`） |

| ショップの武器/お守りのレア度の出やすさ・GAMEごとの上昇度を変える | `js/config.js` の `CONFIG.SHOP_RARITY_BASE_WEIGHTS` / `SHOP_RARITY_GAME_GROWTH` |
| リロール／削除のコスト上昇度合いを変える | `js/config.js` の `CONFIG.SHOP`（`REROLL_*` / `DELETE_*`） |

## 4. 今回の変更点

- **見た目を昔のドット絵RPG風に変更**：フォントを日本語もドット文字で表示できる「DotGothic16」に変更し、パネル・ボタンの角丸を全て廃止して直角に、二重のくっきりしたピクセル枠と押し込み式のボタン（押すと影の分だけずれる）にしました。なめらかなグラデーションだった背景やHPバー、アイコンの仮表示もフラットな色面に変更しています。フォントはGoogle Fontsから読み込むため、オフライン環境では自動的に等幅フォントにフォールバックします（見た目以外の動作に影響はありません）。
- **戦闘バランスの根本修正（最重要）**：GAME 1の序盤で「理論上絶対に倒せない敵」がランダム出現してクリア不能になる問題を修正しました。詳細は次のセクション参照。
- **同時に出現する敵の数をデフォルト1体に変更**（`CONFIG.ENEMY_COUNT`）。
- **戦闘の攻撃チャンス（ターン）を明示的な概念にし、カードで増やせるように**：`CONFIG.MAX_BATTLE_TURNS_PER_ENEMY`（基本3ターン）+ `player.extraTurns`（カード「不屈の闘志」で+1）が実際の攻撃チャンス数になります。
- **ショップの品揃えが重複しない**：武器・お守りそれぞれ、同じ商品が同時に並ばないようにしました。
- **ショップ画面のスクロール対応**：ショップのパネルが画面からはみ出す時、内部できちんとスクロールできるように修正しました（`game-container`がCSSで拡大縮小される都合上、`vh`指定だと画面からはみ出して操作できなくなる不具合があったため、親要素基準の`%`指定に変更）。
- **ショップからの退出手段を強化**：右上の「閉じる」ボタンに加えて、パネル外側の暗い部分をクリックしても閉じられるようにしました。
- **クリティカル率の初期値を2%に変更**。
- **クリティカル率強化の計算方式を変更**：カード・パッシブ・通常のお守りによるクリティカル率強化は「現在値に対して＋N%上昇」という倍率計算にしました（例：2%の時に+10%のカードを取ると 2%×1.10 になる）。実数値（％ポイント）でそのまま加算するのはLEGENDARYのお守り「幸運のお守り」だけの特別な効果とし、1〜5%の範囲でランダムに決まります。
- **アイテムのレア度を5段階に拡張**：NORMAL（白）／RARE（青）／EPIC（紫）／LEGENDARY（金）／PREDATOR（赤）。パッシブ・カード・お守り・武器の名前がレア度に応じて色分け表示されます。
- **レア度の解禁システム**：EPICはGAME4から、LEGENDARYはGAME7から、PREDATORはGAME10から、抽選対象に含まれるようになります（それより前はどれだけ運が良くても出現しません）。
- **ショップの武器・お守りもGAMEが進むほど強いレア度が出やすくなる**：`SHOP_RARITY_GAME_GROWTH`の値ぶん、GAMEを重ねるごとに上位レア度の重みが上がっていきます。
- **リロール・削除のコストが上昇していく**：使うたびに（`REROLL_COST_GROWTH_PER_USE`等）、そしてGAMEが進むほど（`REROLL_COST_GROWTH_PER_GAME`等）、コストが上がっていきます。
- **サイコロを増やすカードを追加**：「二つ目の運命」（LEGENDARY）でサイコロの数を+1できます。


## 4.5. 戦闘バランス修正の詳細

**問題**：GAME 1からHPの高い敵や強敵(STRONG)補正の付いた敵がランダム出現しうる仕様だったため、プレイヤーの判断に関係なく「絶対に倒せない敵」に当たってクリア不能になることがありました。

**修正内容**：

1. **モンスターごとに`minGame`を設定できるようにした**（`CONFIG.MONSTERS`）。GOLEMは`minGame: 2`とし、GAME 1では通常のENEMYマスに出現しなくなりました。
   ```
   { id: "golem", ..., minGame: 2 }
   ```
2. **GAME 1の基本モンスターのHP・報酬を調整**：SLIME(HP8/15G)、GOBLIN(HP14/25G)、ORC(HP24/45G)、GOLEM(HP40/100G、GAME2から)。すべて`CONFIG.MONSTERS`の1箇所で管理しています。
3. **STRONG（強敵）出現率をゲーム番号ごとに変更**（`CONFIG.STRONG_RATE_BY_GAME`）：GAME1=0%、GAME2=10%、GAME3=20%、GAME4以降=25%（`STRONG_RATE_DEFAULT`）。
4. **STRONGのHP倍率もゲーム番号ごとに変更**（`CONFIG.STRONG_HP_MULT_BY_GAME`）：GAME2=×1.5、GAME3以降=×2.0（GAME1は出現率0%のため実質未使用）。これは通常のENEMYマス限定の値で、DANGERマスは従来通り固定のSTRONG倍率(×2)・出現率(50%)を使います（DANGERマスは意図的にリスクが高いマスとして扱うため、今回の安全策の対象外としています）。
5. **通常ENEMYマスでの「安全な敵」抽選フィルタを追加**（`Combat.getSafeMonsterPool`）：`player.attack × (MAX_BATTLE_TURNS_PER_ENEMY + player.extraTurns) × player.attackCount`で計算した「理論最大ダメージ」を超えるHPになりうるモンスターは、STRONGが乗る可能性も含めて抽選対象から除外します。これは固定のGAME数で区切るのではなく、その時点のプレイヤーの実際のステータスを見て動的に判定するため、プレイヤーが強くなれば自動的に対象が広がります（1000回のシミュレーションでGAME1〜4のいずれも、初期ステータスのままで「絶対に倒せない敵」が出現しないことを確認済みです）。
6. **「攻撃チャンス（ターン）を増やすカード」を追加**：「不屈の闘志」（RARE）で戦闘中の攻撃チャンスが+1されます。既存の「二刀の極意」（攻撃回数+1）と組み合わせることで、序盤から選択の幅が広がります。

これらはすべて`config.js`の数値・`minGame`・`STRONG_RATE_BY_GAME`等を書き換えるだけで調整できます。

## 5. 難易度・成長カーブの設計方針（目安）

- GAME 1では、攻撃力10・攻撃回数1・攻撃チャンス3回（理論最大ダメージ30）を基準に、通常のENEMYマスで出現する基本敵（SLIME/GOBLIN/ORC）が必ず3回以内の攻撃で倒せるHPになるよう調整しています。GOLEMとSTRONG補正はGAME1では出現しません。
- レア度の解禁がGAME4・GAME7・GAME10と段階的に進むことで、「今のランでは強力な効果はまだ出ない」という制約が自然な難易度カーブを生みます。
- パッシブ・カード・お守り・武器を積み重ね、かつゲームが進んでレア度の高いアイテムが解禁されていくことで、だいたいGAME10前後（PREDATOR解禁のタイミング）を目安に、敵をワンパンできるくらいの火力に到達することを想定しています。

## 6. 仕様上「明記が無かった／仮に決めた」部分

- **クリティカル率の倍率計算の対象範囲**：「N%上昇」という指定があったのはクリティカル率のみだったため、攻撃力・クリティカルダメージ倍率・攻撃回数などは従来通り実数値の加算のままにしています。
- **カード/お守りの削除とクリティカル率の関係**：倍率で増えたクリティカル率のカード/お守りを削除すると、増やした時と同じ倍率で割り戻します（例：×1.10したものは÷1.10で戻す）。複数の倍率効果を色々な順番で取得・削除すると、計算順序によってごく僅かな誤差が生じる可能性がありますが、プロトタイプの範囲では無視できる程度です。
- **ショップの品揃えの重複回避**：同じ武器/お守りが「同時に」並ばないようにしただけで、リロールのたびに前回と同じ商品が出ること自体は許容しています（品揃え全体の重複防止までは行っていません）。
- **レア度の解禁ゲーム数**：EPIC=GAME4、LEGENDARY=GAME7、PREDATOR=GAME10からとしました（`CONFIG.ITEM_RARITIES`の`unlockGame`で調整可能）。
- **パッシブのレア度**：パッシブはラン開始時に1回だけ選ぶ性質上、レア度による出現制限（解禁システム）の対象外とし、常に全て選択肢に出るようにしています。rarityIdは表示色のためだけに使っています。
- **「絶対に倒せない敵」の安全策の適用範囲**：通常のENEMYマスのみに適用し、DANGERマスには適用していません（DANGERマスは元々「強敵が出やすいリスクのあるマス」という原仕様のため）。また、この安全策は特定のGAME数で切り替わる仕組みではなく、常にその時点のプレイヤーの実際のステータスを見て動的に判定します。プレイヤーが弱いままだと上位モンスターやSTRONGがずっと抽選対象外になり続けますが、これは「対象外＝出現しない」という意図通りの安全側の挙動です。

## 7. 今後の拡張方針

- **武器を外して素手に戻す機能**：`GameState.equipWeapon(null)`を呼べば素手に戻せるので、ショップにその選択肢を1つ追加するだけで実装できます。
- **ショップの品揃えの完全重複回避（リロード含む）**：`Shop.rollOffers()`に「前回のオファーも除外候補に含める」処理を足せば実現できます。
- **確率変化系のパッシブ/カード（RARE率アップ等）**：`player`オブジェクトに補正値を持たせ、`Combat.pickWeighted()`が「基本値＋補正値」を見るように拡張すると管理しやすくなります。
